# UE5 project and interaction integration

The environment provides `Plugins/BenchRuntime`. Enable it and depend on `BenchRuntime` in your gameplay module. Derive your interaction component from `UBenchEntity`, set its stable EntityId and Role from `interaction-contract.json`, and override `Interact_Implementation(APawn*, const FString& Action, const FString& Argument)`. Manual controls and automated calls must use this same gameplay code. Do not edit or replace the provided observer or inventory implementation.

Use a real character pawn with walking/collision and a controllable camera. Provide WASD movement, mouse look, and documented keys for the listed actions. Visible interactive surfaces must block Visibility; walls, floors, door leaves and load-bearing platforms need appropriate Pawn collision. Operations must enforce reach, occlusion, prerequisites and capacity themselves. Use gradual motion with collision and carried objects moving consistently. Give movable items stable individual actors/IDs; transferring an item must not duplicate it. Containers, carts and platforms hold actual visible objects. A carried item's visual identity must survive pickup, placement and transfer. Any inventory counters required by the contract use exactly one supplied UBenchInventory on the pawn, initially empty; no separate competing counter store. ReadCounts supports arbitrary item keys.

The observer accepts plans containing camera, look, look_entity, interact, invoke, walk_to, wait, snapshot, capture, ray, probe and export_geometry. `interact` uses a real 300 cm visibility ray and calls the requested target only if hit; `invoke` is for developer/negative tests and does not bypass candidate preconditions. `fixture` with purpose local_test_setup is permitted for isolated development checks, not continuous task execution. Snapshot state strings are inspection hints; geometry and state transitions are measured independently.

Deliver exactly one root `.uproject`, Source/, Config/, Content/ as needed, README.md, assets_used.json and bindings.json. EngineAssociation is 5.8, BuildSettingsVersion.V7 and EngineIncludeOrderVersion.Latest. Use /Engine/Maps/Entry with your game mode if generating the scene at runtime. All scenery, sky, lights and interaction geometry must exist in play mode.

bindings.json format: version 2; entities maps every required ID to approach_cm and look_cm in centimetres; doors also provide crossing_from_cm and crossing_to_cm, and moving mechanisms may provide endpoints or limits. views maps overview, interior, interaction and each named zone to position_cm, look_cm and horizontal_fov_deg. reference_views maps each supplied reference image ID to a predicted camera in the same scene. workflow supplies ordered task waypoints and interaction steps sufficient to demonstrate the stated continuous activity without teleport/reset. These are location hints, not evidence of success. Supply README controls, startup, initial state, object placements, prerequisites and real limitations.
