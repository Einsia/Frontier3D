# 评测接口与指标

没有标准游戏实现或唯一视觉 GT。Harness 应启动实际 UE5 工程，以输入回放、引擎观测和画面交叉核验；不能只评分演示视频、日志自报结果或静态资源。诊断适配器由评测侧编写，不额外要求受测模型提供隐藏 API。

| 维度 | 指标 | 测法与边界 |
|---|---|---|
| 可执行性 | 工程加载、必要编译、默认地图与菜单启动、缺失依赖率 | 清洁环境使用声明的 UE5 版本启动；以实际可开始并继续比赛为通过依据。 |
| 语义结构 | 双角色、法杖、盒子碰撞、HUD、三种大招覆盖 | 核对场景和蓝图/源码及实际交互；Blender 源资产与 UE5 可见资产应语义对应，不要求同名对象或说明迁移步骤。 |
| 物理交互 | 发射方向、反冲线/角动量、限速、墙面响应 | 多种姿态和速度下发射，测前后速度、角速度与碰撞；核对偏置冲量并扣除阻尼，不能用预设位移动画冒充。容差需按物理步长校准。 |
| 战斗规则 | 伤害、弹速/寿命、单次命中、能量、冷却、持续伤害 | 使用命中、擦边、墙挡、自身忽略、资源不足、死亡取消等输入场景，逐项对照 prompt 数值。 |
| 时间一致性 | 不同渲染帧率下的逻辑结果与力场积分差异 | 固定种子和输入时间戳，以多档渲染帧率回放；比较 60 Hz 逻辑和物理事件，允许浮点容差，不要求截图逐像素一致。 |
| AI | 同规则行动、有效攻击、避险行为、难度差异 | 多种出生状态、多种种子和有界观察窗口；检查决策频率、转向限速，不用单场胜负或固定动作序列替代能力评价。 |
| 可玩性与流程 | 操作反馈、视野保持、暂停、局间重置、重复重赛稳定性 | 自动走完整局/超时/同时死亡/重赛流程，统计失控和卡死；画面可读性另列结构化人工评审，不以 LLM 总分替代规则检查。 |
| 工程质量 | Blender/UE5 资产可编辑、依赖齐全、可复现启动 | 检查实际源文件和工程引用；未实现的菜单按钮、占位特效、只存在于代码中的功能不得计作完成。 |
| 效率 | token、生成耗时、调用、编译与运行失败成本 | Harness 统一记录，质量与成本分别报告；帧率必须注明机器与画质设置。 |

先验证启动和关键交互，再做长局与多次重赛。未知对象名可通过语义、碰撞体、事件与屏幕区域定位。当前没有 evaluator 实现，也没有模型实测分数。

## 视觉参考的评测边界

`input/reference.png` 是模型已知的视觉方向，不是隐藏 GT。评测场景造型、配色协调、主体辨识度、相机可读性及交互反馈；使用提交 UE5 工程的实际运行画面核验。不得以逐像素相似度、图中任意物体位置或 HUD 样式作为硬性通过条件，也不能把概念图当作真实物理状态。文字规格优先，画面评分与规则/物理评分分开报告。
