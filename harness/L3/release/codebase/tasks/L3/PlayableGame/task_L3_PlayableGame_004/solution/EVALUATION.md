# 评测接口与指标

评测首先读取 `output/ue5_project/3DBenchGame.uproject` 和 `output/README.md`，再按默认地图和实际交互检查。没有唯一视觉 GT；重点是物理、规则和可复现性。Harness 不要求模型额外提供隐藏 API。

| 维度 | 指标 | 测法与边界 |
|---|---|---|
| 可执行性 | 工程加载、默认地图、菜单、重开 | 清洁 UE5 环境启动并完成至少一局；记录缺失依赖、崩溃和残留状态。 |
| 场地与语义 | 10×10 m 平台、边界、四类物块、独立刚体 | 从工程和运行时碰撞检查平台尺寸、形状类别、闭合网格、独立可编辑性；不依赖对象名。 |
| 操控 | 固定悬停平面、X/Y 平移、三轴旋转、释放 | 回放多组输入，测控制连续性、旋转轴和释放瞬间；禁止网格吸附、瞬移和释放后脚本修正。 |
| 物理 | 重力、碰撞、摩擦、倾倒、支撑 | 观察接触、堆叠、滚落和边缘情况；与工程声明的质量/摩擦/恢复系数交叉核验。 |
| 稳定判定 | 0.05 m/s、5°/s、2 s 稳定窗口 | 在不同帧率下回放相同输入，测稳定倒计时和下一回合触发；不能依赖渲染帧计时。 |
| 结束与计分 | 跌落/越界、5 s 不稳定、最高稳定高度、厘米分数 | 构造边缘释放、整塔倾倒和轻微碰撞案例；核对结束条件、分数和结果画面。 |
| 随机与复现 | 默认种子、可改种子、物块序列 | 相同种子和输入应复现类型序列；不同种子应能产生不同序列，不要求几何逐位相同。 |
| 流程与可玩性 | HUD、相机跟随、反馈、重赛清理 | 完成多局并检查旧刚体、定时器、音效和 UI 是否残留；人工评审几何可读性。 |
| 工程质量 | UE5/Blender 可编辑、依赖本地化 | 检查项目引用、源资产和 README；不以视频或静态截图代替可运行工程。 |
| 效率 | token、耗时、调用、失败成本 | Harness 统一记录，质量与成本分开报告。 |

先进行启动、控制和物理短回放，再进行长塔和多局稳定性测试。当前没有 evaluator 实现或模型实测分数。

## 视觉参考的评测边界

`input/reference.png` 是模型已知的视觉方向，不是隐藏 GT。评测场景造型、配色协调、主体辨识度、相机可读性及交互反馈；使用提交 UE5 工程的实际运行画面核验。不得以逐像素相似度、图中任意物体位置或 HUD 样式作为硬性通过条件，也不能把概念图当作真实物理状态。文字规格优先，画面评分与规则/物理评分分开报告。
