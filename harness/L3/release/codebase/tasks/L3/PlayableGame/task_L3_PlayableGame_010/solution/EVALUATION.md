# 抓钩摆荡跑酷：评测设计

任务设计已入库，没有标准答案游戏、evaluator 实现或实测成绩。仅将 instruction.md 和 environment/ 暴露给模型；solution/ 留在评测侧。

评测入口固定为 `output/ue5_project/3DBenchGame.uproject`，说明为 `output/README.md`。评测侧通过输入回放、引擎状态观测和实际画面交叉验证，可编写独立的工程适配器，不要求模型实现隐藏 API，也不依赖固定 Actor 名称或模型自报的成功日志。所有硬性条件来自公开 prompt。

| 维度 | 操作与观测 | 判定要点 |
|---|---|---|
| 启动与交付 | 清洁环境加载固定 uproject，进入游戏并重复重开 | 记录加载/编译结果、缺失依赖和运行错误；真实交互不能用视频代替。 |
| 连接条件 | 超距、遮挡、瞄空、多次连接 | 15m限制及射线可见性有效；最多一根绳。 |
| 摆荡与释放 | 固定锚点摆荡、松绳、松弛再张紧 | 测距离约束和速度连续性；禁止固定轨迹或速度凭空归零。 |
| 检查点 | 落台、擦过、坠落、危险碰撞 | 仅真实落地解锁；复活位置、速度和绳状态正确。 |
| 生成与回收 | 连续通过模块、同种子重试 | 同种子复现平台间距与锚点序列，不同种子及连续平台呈现间距变化且在公开范围内；结合实际运动参数验证摆荡/释放落地路径，不能仅检查15m锚点距离；回收不能删除当前检查点或眼前平台。 |
| 视觉与可玩性 | 从实际运行工程采集画面并走完整循环 | 核查纯色几何、主体/目标可辨、相机遮挡、操作反馈；人工可读性评分与程序检查分开，不做概念图像素对齐。 |
| 稳定性与成本 | 固定种子和输入时序，在30/60/120渲染帧率下回放；重复重开 | 比较事件顺序/计数和容差内状态；物理容差先校准。记录token、耗时、工具调用和运行失败，不用模型自报。 |

先测启动和单一交互，再跑多轮循环与失败边界。未知数值按提交 README 与实际工程交叉核验；未公开容差先在有效实现上标定。规则/计数可做确定性断言，物理状态用容差；不把某条唯一操作路线、最优策略或特定画面当作标准答案。

模型可见的 `input/reference.png` 用于简洁美术与画面可读性参考，不是运行截图或隐藏几何真值；规则以双语 instruction 为准。
