请用 Blender + UE5 制作一个原创、可实际游玩的第三人称三维单场地 PvE roguelike，采用克制的几何风格。玩家从手枪开始，在一个可重复使用的场地中击退越来越强的敌人潮，在每关之间选择升级并继续挑战，直到胜利或死亡。必须是实际可交互的游戏循环，不能用固定战斗动画或菜单样机代替。

创建一个约 32 m × 24 m 的封闭战斗场地，包含清楚的地面、边界墙或等效阻挡、少量低矮障碍和明确出生区。整局使用同一个场地；重新开始时清理并重置角色和掉落物。使用第三人称相机，让玩家、附近敌人和瞄准方向清楚可读，不能穿出场地。美术可以抽象和几何化，但角色、武器、投射物和敌人必须有可见轮廓并使用真实碰撞。

每局从手枪、100 点生命、12 发弹匣和零升级开始。提供写在 README 中的操作：WASD 移动、鼠标瞄准、鼠标左键射击、R 换弹、Shift 冲刺或闪避（如果实现）、Esc 暂停。手枪必须有有限弹匣、换弹时间以及可在工程中检查的投射物或射线行为。伤害、射击间隔、射程和换弹数值要在 README 中声明，并由运行中的游戏实际执行。不能给玩家隐藏的伤害、生命或弹药加成。

每一关由一波敌人和一次升级选择组成。第一关从 6 个敌人开始，后续关卡提高总威胁。至少提供三类敌人：会向玩家导航并近距离攻击的近战追击者；保持距离并发射可见投射物的远程敌人；生命更高、攻击前有明显前摇的慢速重型敌人。敌人必须使用真实碰撞和导航或转向，不能瞬移到攻击距离，也不能读取玩家未来输入。敌人的生命、移动、攻击时序和投射物规则要能从工程或 README 检查。

一波敌人全部被击败后暂停战斗，展示三个升级选项。整局中必须覆盖这些升级类别：武器伤害或投射物行为、射速或弹匣/换弹、最大生命或治疗、移动/冲刺装备，以及防御或功能效果。选择必须实际更新玩家状态和 HUD，并持续到后续关卡；新局开始时清空。不能只展示三个不同名字但底层数值不变的选项。玩家选择一张卡后，经过短暂过渡再开始下一波。

提供 6 关或其他明确写出的有限流程，并逐关增加敌人数量或强度。第一关应能用初始手枪完成。后续关卡通过敌人组合、生命、攻击频率或出生模式增加压力，不能靠无法规避的预设命中。完成最终关后显示胜利画面、分数和已选升级；死亡时显示结束画面，并提供重新开始和返回菜单。重复重开必须清除旧敌人、投射物、掉落物、计时器和升级状态。

使用独立于渲染帧率的固定 60 Hz 游戏更新。默认随机种子为 20260922，并可通过小型设置面板或文档化启动参数修改。种子控制敌人组合和升级选项；相同种子加相同玩家输入序列必须复现这些选择。HUD 显示当前关卡、波次状态、生命、弹匣、换弹状态、已选升级和分数。为命中、换弹、受伤、升级和胜利提供克制的反馈。只要求单机，不要求联网。
