# 评测接口与指标

评测首先读取 `output/ue5_project/3DBenchGame.uproject` 和 `output/README.md`，再启动默认地图并进行输入回放。没有唯一视觉 GT；评分重点是战斗循环、状态变化、敌人行为、升级和可复现性。Harness 不要求模型额外提供隐藏 API。

| 维度 | 指标 | 测法与边界 |
|---|---|---|
| 可执行性 | 工程加载、默认地图、菜单、暂停、重开 | 清洁 UE5 环境启动；完成开始、战斗、升级、死亡和重开流程，记录依赖和崩溃。 |
| 场地与相机 | 单一 32×24 m 左右场地、边界、障碍、第三人称视角 | 检查碰撞边界、出生区、相机遮挡和玩家/敌人可读性；不要求固定网格或美术风格。 |
| 初始武器 | 手枪、100 生命、12 发弹匣、换弹和射击规则 | 新局读取实际状态，回放射击/换弹，测伤害、弹药消耗、射速、射程和换弹时间。 |
| 敌人 AI | 近战、远程、重型三类及真实移动/攻击 | 在多种出生位置观察导航、攻击前摇、投射物和碰撞；禁止瞬移、未来输入和脚本必胜。 |
| 波次流程 | 第一关 6 敌人、逐关增强、至少 6 关或等价流程 | 清除一波后必须进入升级选择；构造击杀、漏怪、死亡和最终胜利案例。 |
| 升级 | 三选一、至少五类升级、状态持久化、重新开始清空 | 对每张升级卡记录前后属性和实际战斗效果；不能只改 UI 文本。 |
| 时间与随机 | 固定 60 Hz、默认种子、可改种子、复现 | 固定种子和输入回放，比较敌人组合和升级选择；多渲染帧率下逻辑结果允许浮点误差。 |
| 可玩性与反馈 | HUD、命中、换弹、受伤、升级、胜利/死亡反馈 | 自动走完整局并多次重赛，检查旧 Actor、计时器、投射物和升级是否清理。 |
| 工程质量 | UE5/Blender 资产可编辑、依赖齐全 | 检查源码/蓝图、碰撞、源资产和 README；视频不能代替工程。 |
| 效率 | token、耗时、调用、编译和运行失败成本 | Harness 统一记录，质量与成本分开报告。 |

先做启动、射击、敌人移动和一波流程测试，再做升级、长流程和多次重开测试。当前没有 evaluator 实现或模型实测分数。

## 视觉参考的评测边界

`input/reference.png` 是模型已知的视觉方向，不是隐藏 GT。评测场景造型、配色协调、主体辨识度、相机可读性及交互反馈；使用提交 UE5 工程的实际运行画面核验。不得以逐像素相似度、图中任意物体位置或 HUD 样式作为硬性通过条件，也不能把概念图当作真实物理状态。文字规格优先，画面评分与规则/物理评分分开报告。
