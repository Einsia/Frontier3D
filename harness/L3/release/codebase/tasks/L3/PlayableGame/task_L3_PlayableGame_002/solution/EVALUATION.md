# Evaluation reference

没有参考游戏或唯一地图；solution/ 只放评测说明和概念图来源记录。

| 维度 | 指标 | 如何测量 | 报告结果与判定 |
| --- | --- | --- | --- |
| 可执行性 Executable | UE5 工程启动与运行稳定性 | 在声明的 UE5 版本和统一机器上打开工程，必要时构建，启动默认关卡；检查依赖并进行探索/建造运行。 | 首次启动成功率、崩溃/运行错误、连续可玩时长；打包仅作评测环境步骤，不额外要求提交未在 prompt 中规定的安装包。 |
| 结构 Structural | 方块与世界内容覆盖 | 在实际世界中核对 8 类基础内容、5 类地形及其语义表现，检查它们是否属于同一可探索空间。 | 内容/地形覆盖率、缺失类别、可抵达地形；不能仅凭资源目录或截图中存在便判功能完成。 |
| 几何 Geometric | 移动、碰撞与合法放置 | 执行行走、观察、跳跃，在实体、地形边缘与玩家占位附近尝试移动和放置；比较可见表面与碰撞响应。 | 合法动作成功率、穿模次数、非法放置阻止率和碰撞更新错误；场景采样规则在正式比较前固定。 |
| 任务与状态 Task & State | 破坏—收集—放置闭环 | 选择不同可破坏材料，记录破坏前后世界、掉落、收集、库存和放置结果；测试重复操作与库存不足。 | 闭环完成率、库存增减正确率、丢失/重复资源/无成本放置次数；按材料和操作类型分别报告。 |
| 结构 / 任务状态 | 规则、交互与显示一致性 | 检查快捷选择、火把可放置并发光、水体有明确交互；修改方块后核对世界几何、渲染和碰撞一起更新。 | 功能满足率、显示与实际状态不一致次数、火把/水规则缺陷；不要求复杂流体或 prompt 未要求的生存系统。 |
| 任务与状态 Task & State | 生成确定性与存档恢复 | 同种子重建并比较可观测世界；挖掘和建造后存读档，对比玩家、地形、库存和后续随机过程。 | 重复生成一致性、保存/恢复成功率、字段/行为差异；以声明的存档语义检查，不规定序列化格式或 API。 |
| 任务与状态 Task & State | 开放玩法与可继续游玩 | 选择不同地点与材料完成自由探索、挖通道、搭建简单结构、拆改再建等操作组合，并在中断后继续。 | 不同操作组合的完成率、软锁/无法继续次数；不把建筑造型或操作顺序作为唯一答案。 |
| 视觉 Visual | 游戏可读性与体验 | 盲评地形/材料区分、选中目标和库存反馈、视角操控及探索意愿；概念图仅作方向参考。 | 可理解性、反馈清晰度与人工成对偏好；外观/VLM 辅助结果独立，不按 Minecraft 外观或概念图像素匹配。 |
| 结构 / 任务状态 | Blender + UE5 内容与语义一致性 | 检查 UE5 中生成资产的尺度、材质、碰撞和交互是否一致；仅在评测过程能取得 Blender 侧对应资产时，进一步比较两侧。 | UE5 资产—碰撞—交互一致率；跨引擎可比项的几何/材质/语义差异另报，缺少可比证据标记不可测，不要求额外迁移文档或中间格式。 |
| 可执行性 / 效率 | 运行性能与逻辑步长 | 统一硬件、分辨率和探索/建造负载，记录帧时间、内存及卡顿，核对 20 Hz 逻辑更新和大量方块修改后的稳定性。 | 帧时间 p50/p95/p99、平均 FPS、峰值内存、长帧数及逻辑频率；负载和性能通过线待标定，不混同渲染帧率与逻辑频率。 |
| 效率 Efficiency | 生成成本与反馈收益 | Harness 记录总耗时、token、工具调用、渲染次数及失败重试；若采用视觉反馈，分别记录初稿、每轮修改与最终结果，单次生成和最多 3 轮修改分组比较。 | 报告总成本、各轮指标变化及每次质量改善的额外成本；固定模型设置、环境和预算，不把失败运行从成本统计中删除。预算与综合权重待标定。 |

阈值依据英文 instruction；未明示项须在正式比较前标定。程序化、视觉辅助与人工结果分列，不合成未经校准的总分。运行失败保留原因；原生资产自检不代表完整 evaluator 已实现。

## 视觉参考的评测边界

`input/reference.png` 是模型已知的视觉方向，不是隐藏 GT。评测场景造型、配色协调、主体辨识度、相机可读性及交互反馈；使用提交 UE5 工程的实际运行画面核验。不得以逐像素相似度、图中任意物体位置或 HUD 样式作为硬性通过条件，也不能把概念图当作真实物理状态。文字规格优先，画面评分与规则/物理评分分开报告。
